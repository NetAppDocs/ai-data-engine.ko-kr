= AI Data Engine용 프록시에 대해 알아보기
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine(AIDE) 호스트 또는 클러스터가 인터넷에 직접 연결할 수 없는 경우, 설치 프로그램과 AI Data Engine이 구성 요소를 다운로드하고, 컨테이너 이미지를 가져오고, NetApp Console에 등록할 수 있도록 포워드 프록시를 구성하십시오. 프록시 옵션은 단일 노드 및 다중 노드 배포에 대해 동일합니다. 설치를 준비하고 실행하는 단계가 다르므로 각 배포 유형에는 고유한 워크플로가 있습니다.

프록시 설정은 호스트 시스템이 아닌 k3s 런타임 및 AI Data Engine에만 적용됩니다.



[[deploy-ai-data-engine-with-a-proxy]]
== 프록시를 사용하여 AI Data Engine 배포

각 배포 유형마다 환경 준비부터 설치 프로그램 실행까지 전체 절차가 담긴 별도의 항목이 있습니다.

* link:deploy-aide-single-node-proxy.html["프록시를 사용하여 AI Data Engine을 단일 노드 배포로 배포"]: 설치 프로그램은 트러스트 스토어를 포함하여 k3s 런타임 및 AI Data Engine에 대한 프록시를 구성합니다.
* link:deploy-aide-multi-node-proxy.html["프록시를 사용하여 다중 노드 배포로 AI Data Engine 배포"]: 설치 프로그램을 실행하기 전에 모든 노드에서 컨테이너 런타임 프록시와 CA 인증서 신뢰를 구성합니다.




[[what-goes-through-the-proxy]]
== 프록시를 통과하는 항목

인터넷 바운드 트래픽만 프록시를 사용합니다. 모든 AI Data Engine 인터넷 대상은 포트 443에서 HTTPS를 사용하므로, 프록시는 link:aide-requirements.html#outbound-internet-access["아웃바운드 인터넷 액세스"]의 각 엔드포인트에 대해 포트 443으로  `CONNECT`을(를) 허용해야 합니다.

네트워크의 트래픽은 직접 연결되며 프록시 없이도 도달 가능해야 합니다:

* 콘솔 에이전트 (`--cm-host`)
* NFS, CIFS/SMB, ONTAP 및 StorageGRID 데이터 소스
* Active Directory 및 LDAP
* 쿠버네티스 API 서버와 클러스터의 내부 네트워크




[[supported-proxy-configurations]]
== 지원되는 프록시 구성

[cols="2,3,2"]
|===
| 구성 | 설명 | 인증 


| 프록시 없음 | 인터넷에 직접 연결되며, 프록시를 사용하지 않습니다. | None 


| HTTP 포워드 프록시 | AI Data Engine은 HTTP를 통해 프록시에 연결하고  `CONNECT`을(를) 사용하여 HTTPS 대상을 터널링합니다. | 없음 또는 HTTP 기본 인증(사용자 이름 및 비밀번호) 


| HTTPS 포워드 프록시 | AI Data Engine은 TLS를 통해 프록시에 연결합니다. 사설 인증 기관(CA)이 프록시 인증서에 서명한 경우, CA 인증서를 제공합니다. | 없음 또는 HTTP 기본 인증(사용자 이름 및 비밀번호) 
|===
호스트 이름 또는 IPv4 주소로 프록시를 지정할 수 있습니다.


IMPORTANT: AI Data Engine은 HTTPS 대상을 포함하여 HTTP `CONNECT`로 연결을 터널링하는 표준 포워드 프록시를 지원합니다. 프록시에서 TLS 트래픽을 검사하는 경우, 설치 프로그램 다운로드 호스트를 포함하여 link:aide-requirements.html#outbound-internet-access["아웃바운드 인터넷 액세스"]의 엔드포인트를 검사에서 제외해야 합니다. TLS 검사 프록시 및 일부 다른 프록시 기능은 지원되지 않습니다. link:../release-notes/known-limitations.html["알려진 제한 사항"]을(를) 참조하십시오.

설치 프로그램은 모든 인터넷 목적지와 모든 AI Data Engine 구성 요소에 대해 하나의 프록시를 사용합니다. 프록시 설정은 설치 중에 설정됩니다.



[[proxy-configuration-parameters]]
[[proxy-parameters]]
== 프록시 구성 매개변수

[cols="2,1,3"]
|===
| 매개변수 | 기본값 | 설명 


| `--proxy-host <host[:port]>` | None |  `http://` 또는 `https://`가 없는 포워드 프록시의 호스트 이름 또는 IPv4 주소입니다. 프록시 구성을 활성화합니다. 인라인 포트를 허용합니다(`host:port`).  `--proxy-host`의 포트가 `--proxy-port`보다 우선합니다. 


| `--proxy-port <port>` | `80` HTTP의 경우,  `443` HTTPS의 경우 | 프록시가 수신 대기하는 포트입니다. 포트가  `--proxy-host`에 이미 포함되어 있으면 무시됩니다. 


| `--proxy-scheme <http|https>` | `https` | 프록시 서버 자체에 연결하는 데 사용되는 프로토콜입니다. 이는 프록시가 도달하는 목적지의 체계가 아닙니다. 대부분의 포워드 프록시는 일반 HTTP로 수신 대기하므로 해당 프록시에는  `--proxy-scheme http`을(를) 전달하십시오. 


| `--proxy-ca-cert <path>` | None | 프록시 인증서에 서명한 CA 인증서가 포함된 PEM 파일, 또는  `.crt` 및  `.pem` 파일로 구성된 플랫 디렉터리의 경로입니다. 설치 프로그램은 하위 디렉터리를 탐색하지 않고 디렉터리를 읽어 파일을 하나의 번들로 병합합니다. 인증서를 개인 CA가 서명한 HTTPS 프록시에 필요합니다. HTTP 프록시에서는 사용되지 않습니다. 


| `--proxy-user <user>` | None | 기본 인증을 위한 사용자 이름입니다. HTTP 프록시를 사용하는 경우, 설치 프로그램은 자격 증명이 암호화되지 않은 상태로 프록시로 전송된다고 경고합니다. 암호가 필요하며,  `--proxy-password-file`와 함께 제공하거나 프롬프트에서 입력해야 합니다. 


| `--proxy-password-file <path>` | None | 프록시 암호만 포함된 로컬 파일의 경로이며, 권한은  `0600` 또는  `0400`(으)로 설정되어야 합니다. 이를 생략하면 설치 프로그램에서 숨겨진 입력란을 통해 암호를 입력하라는 메시지가 표시됩니다. 


| `--proxy-type <r>` | `r` | 프록시 유형입니다.  `r`은(는) 일반 포워드 프록시이며 기본값입니다. 변경하지 마십시오. TLS 검사 프록시는 지원되지 않습니다. 


| `--no-proxy` | — | 프록시 구성을 명시적으로 비활성화하고 프록시 프롬프트를 건너뜁니다. 호스트가 인터넷에 직접 액세스할 수 있는 경우에만 사용하십시오. 
|===

NOTE: 설치 프로그램은  `--proxy-password` 또는  `PROXY_PASSWORD` 환경 변수를 허용하지 않습니다. 대신  `--proxy-password-file` 또는 대화형 프롬프트를 사용하십시오.



[[the-installer-download]]
== 설치 프로그램 다운로드

NetApp Console에서 복사한 설치 명령은 콘텐츠 전송 네트워크(CDN)에서 설치 프로그램을 다운로드한 다음 한 단계로 실행합니다. 다운로드는 프록시를 사용하지 않습니다. 대상 호스트가 프록시를 통해서만 인터넷에 연결되는 경우, 설치 프로그램을 직접 다운로드하고 압축 해제된 설치 프로그램에서 설치 명령을 실행합니다. 배포 항목에서 이러한 단계를 설명합니다.



[[proxy-verification]]
== 프록시 검증

설치 프로그램은 파일을 다운로드하기 전에 설치 호스트에서 검사를 실행합니다. 이 검사는 프록시가 응답하는지, 프록시가 사용자의 자격 증명을 수락하는지, 프록시 인증서가 사용자가 선택한 체계에 대해 유효한지 확인합니다. 검사에 실패하면 설치 프로그램이 중단되고 잘못된 포트, 잘못된 체계 또는 거부된 암호(HTTP 407) 등 그 원인을 표시합니다.

다중 노드 배포의 경우, 이 검사는 프록시만 대상으로 합니다. 클러스터 노드가 프록시에 도달할 수 있는지 여부는 테스트하지 않습니다.



[[change-proxy-settings-after-installation]]
== 설치 후 프록시 설정 변경

프록시 설정은 설치 중에 설정됩니다. 설치된 클러스터에서는 설치 프로그램이 다시 실행되지 않습니다. 설치 후 프록시 호스트, 포트, 자격 증명 또는 CA 인증서를 변경하려면 NetApp 지원팀에 문의하십시오.
