= AI Data Engine이 관리하는 AI 액세스를 위해 MCP 호스트를 준비합니다.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI 클라이언트가 AI Data Engine MCP 서버에 연결하는 데 사용하는 AI Data Engine(AIDE) 클러스터 호스트 이름과 인증서를 설정합니다. Entra ID의 Application ID URI는 AIDE 클러스터 호스트 이름에서 생성되므로, Microsoft Entra ID를 구성하기 전에 이 작업을 완료하십시오.

이 작업에서는 스크립트를 실행하여 도메인과 인증서를 설정하고, 클라이언트 컴퓨터가 호스트에 연결할 수 있는지 확인한 다음 호스트를 검증합니다.


NOTE: Microsoft는 Microsoft Entra ID UI를 변경할 수 있으므로 단계 및 경로가 표시되는 내용과 다를 수 있습니다. 필수 구성은 동일하게 유지됩니다.



[[before-you-begin]]
== 시작하기 전에

* AI Data Engine이 배포되었습니다. MCP 서버는 AI Data Engine과 함께 배포되므로 별도로 설치할 필요가 없습니다.
* AI Data Engine이 실행되는 클러스터에 접근할 수 있습니다.
* Microsoft Entra ID 테넌트에서 확인된 등록된 DNS 도메인 이름이 있습니다. AIDE 클러스터 호스트 이름은 이 도메인에 있어야 합니다. <<verified-domain-requirement,검증된 도메인 요구 사항>>을(를) 참조하십시오.




[[verified-domain-requirement]]
== 검증된 도메인 요구 사항

AIDE 클러스터 호스트 이름은 회사의 Microsoft Entra ID 테넌트에서 확인된 등록된 DNS 도메인에 있어야 합니다. 인그레스 스크립트가 설정하는 호스트 이름은 애플리케이션 ID URI에서  `<host>`가 되므로 애플리케이션을 등록하기 전에 도메인을 확인해야 합니다.

AI Data Engine은 Microsoft Entra ID에 등록하는 애플리케이션의 애플리케이션 ID URI로 `\https://<host>/mcp/tools`을(를) 사용합니다. Microsoft Entra ID는 인증된 도메인에 있는 애플리케이션 ID URI만 허용합니다.  `.cluster.local` 호스트 이름 등 확인되지 않은 도메인의 호스트는 사용할 수 없습니다.

인증된 도메인을 확인하려면 Microsoft Entra 관리 센터에서 *Entra ID* > *도메인 이름*으로 이동하십시오.



[[run-the-ingress-script]]
== 인그레스 스크립트를 실행합니다

인그레스 스크립트는 AI 클라이언트가 클러스터 외부에서 MCP 서버에 접근할 수 있도록 다음 항목들을 설정합니다:

* 인증서
* 클러스터 호스트 이름
* 클러스터 호스트 이름에 대한 트래픽을 MCP 서버로 라우팅하는 Kubernetes 인그레스 규칙


.단계
. AI Data Engine 설치 프로그램을 다운로드한 시스템에서 설치 프로그램의 스크립트 폴더를 엽니다: `/tmp/installer/runbook/ingress-manager-scripts/scripts/`. 인그레스 스크립트는 설치 프로그램의 일부로 다운로드됩니다. 폴더가 없는 경우 <<restore-the-ingress-script,인그레스 스크립트를 복원합니다>>를 참조하십시오.
. 인그레스 스크립트를 실행하십시오:
+
[source, bash]
----
./ingress-manager.sh
----
. 스크립트가 설정하는 호스트 이름을 기록해 두십시오. 애플리케이션 ID URI, 범위 및 AI 클라이언트 구성에서 이 호스트 이름을  `<host>`(으)로 사용합니다.



NOTE: 스크립트가 설정하는 호스트 이름은 AIDE 클러스터의 호스트 이름입니다. 스크립트가 완료된 후 AI Data Engine UI에서도 호스트 이름을 확인할 수 있습니다. *구성* > *MCP 컬렉션* > *MCP 설정*으로 이동하여 *MCP 호스트 이름*을 확인하십시오.

스크립트가 자체 서명 인증서를 생성하는 경우 AI 클라이언트를 실행하는 모든 컴퓨터는 해당 인증서를 신뢰해야 합니다. <<make-the-host-reachable,클라이언트 컴퓨터에서 호스트에 접근할 수 있도록 설정하십시오.>>을(를) 참조하십시오.



[[restore-the-ingress-script]]
=== 인그레스 스크립트를 복원합니다

설치 프로그램 폴더는 기본적으로 임시 디렉터리에 있습니다. 시스템이 다시 시작될 때 운영 체제가 임시 디렉터리를 삭제할 수 있습니다. 스크립트 폴더가 시스템에 더 이상 없는 경우 설치 프로그램을 다시 다운로드하고 압축을 해제한 다음 스크립트를 실행하십시오.

.단계
. 스크립트를 실행하는 시스템에서 설치 프로그램을 다운로드하고 압축을 해제하십시오:
+
[source, bash]
----
curl -fsSL https://d13jb5dapseb36.cloudfront.net/aide/latest/aide-installer.tar.gz | tar -xzf - -C /tmp
----
. 스크립트 폴더를 열고 인그레스 스크립트를 실행하십시오:
+
[source, bash]
----
cd /tmp/installer/runbook/ingress-manager-scripts/scripts/
./ingress-manager.sh
----


재시작 후에도 스크립트를 유지하려면 재시작 시 지워지지 않는 디렉토리에 설치 프로그램을 추출하십시오.  `/tmp`을  `tar` 명령과  `cd` 명령에서 해당 디렉토리로 교체하십시오.

[[make-the-host-reachable]]
== 클라이언트 컴퓨터에서 호스트에 접근할 수 있도록 설정하십시오.

AI 클라이언트를 실행하는 모든 기기는 다음을 수행할 수 있어야 합니다:

* DNS를 통해 호스트 이름을 확인합니다.
* 회사 네트워크 또는 VPN을 통해 HTTPS로 443번 포트를 사용하여 호스트에 접속하십시오.
* 호스트가 제시하는 인증서를 신뢰하십시오. 인증서가 자체 서명된 경우, 각 클라이언트 컴퓨터에 신뢰할 수 있는 인증서로 설치하십시오.
* Microsoft Entra ID 로그인으로 이동합니다 (`login.microsoftonline.com`).




[[verify-the-host]]
== 호스트를 확인하십시오

MCP 서버가 AIDE 클러스터 호스트 이름에 응답하는지 확인합니다. MCP 서버는 잘 알려진 엔드포인트에 메타데이터를 게시합니다. 응답을 통해 호스트 이름, 도메인 및 MCP 서버가 올바르게 설정되었는지 확인할 수 있습니다.

.단계
. 클라이언트 컴퓨터에서 MCP 서버의 잘 알려진 엔드포인트를 요청합니다.  `<host>`을(를) AIDE 클러스터 호스트 이름으로 바꿉니다:
+
[source, bash]
----
curl -sk https://<host>/.well-known/oauth-protected-resource/mcp/tools
----
. 응답이 다음 예와 유사한지 확인하십시오. 이 예는 호스트 이름 `aide-cluster.contoso.com`에 대한 명령과 응답을 보여줍니다.
+
[listing]
----
curl -sk https://aide-cluster.contoso.com/.well-known/oauth-protected-resource/mcp/tools | python3 -m json.tool
{
    "resource": "https://aide-cluster.contoso.com/mcp/tools",
    "authorization_servers": [
        "https://login.microsoftonline.com/7f3e2a91-4b6c-4d58-9a0e-2c81d5f6b347/v2.0"
    ],
    "scopes_supported": [
        "https://aide-cluster.contoso.com/mcp/tools/power_users"
    ],
    "bearer_methods_supported": [
        "header"
    ],
    "resource_name": "NetApp AI Data Engine MCP Server"
}
----
+
응답에서 다음 사항을 확인하십시오:

+
** `resource`은(는) `\https://<host>/mcp/tools`이며, 예를 들어 `"resource": "https://aide-cluster.contoso.com/mcp/tools"`와 같습니다. 이는 Microsoft Entra ID에 등록하는 애플리케이션 ID URI입니다.
** `authorization_servers`은(는)  `https://login.microsoftonline.com/7f3e2a91-4b6c-4d58-9a0e-2c81d5f6b347/v2.0`와(과) 같이 Microsoft Entra ID 테넌트를 가리킵니다.
** `scopes_supported`은(는) 호스트 이름에 `power_users` 범위를 포함합니다( `https://aide-cluster.contoso.com/mcp/tools/power_users` 참조).
** `resource_name`입니다 `NetApp AI Data Engine MCP Server`.


. 선택 사항: 추가 확인을 위해 토큰 없이  `\https://<host>/mcp/tools`을(를) 요청하십시오:
+
[source, bash]
----
curl -i https://<host>/mcp/tools
----
+
 `401 Unauthorized` 응답이 예상됩니다. 이 요청은 인증서 유효성 검사를 건너뛰지 않으므로 클라이언트 컴퓨터가 인증서를 신뢰한다는 것도 확인합니다.




IMPORTANT:  `401` 응답만으로는 구성이 제대로 작동하는지 증명할 수 없습니다. 이전에 다른 인그레스가 구성된 경우, MCP 서버가 응답하지 않더라도  `401`을(를) 반환할 수 있습니다. 호스트를 확인하려면 잘 알려진 엔드포인트 응답을 사용하십시오.
