= 관리되는 AI 액세스를 위해 AI Data Engine을 Microsoft Entra ID에 연결하십시오.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Microsoft Entra ID를 AI Data Engine(AIDE)에 ID 공급자로 연결하여 모델 컨텍스트 프로토콜(MCP)을 통해 사용자를 인증하고 사용자가 작업할 수 있는 컬렉션을 제어할 수 있습니다. AI Data Engine 관리자로서 ID 공급자를 설정하고, MCP용 컬렉션을 구성하고, NetApp Console에서 구성을 확인합니다.

관리형 AI 액세스는 Entra ID를 사용하여 사용자를 인증하며, 각 컬렉션에 포함하는 범위에 따라 사용자가 MCP를 통해 작업할 수 있는 컬렉션이 결정됩니다.



[[before-you-begin]]
== 시작하기 전에

* _AI Data Engine 관리자_ 역할이 있어야 합니다.
* AI Data Engine이 배포되었으며 하나 이상의 데이터 소스를 스캔했습니다. link:../data-sources/connect-data-source.html["데이터 소스 연결"]을(를) 참조하십시오.
* AIDE 클러스터 호스트 이름은 Entra ID 테넌트에서 확인된 등록된 DNS 도메인에 설정됩니다. link:prepare-mcp-host.html["MCP 호스트를 준비합니다"]을(를) 참조하십시오.
* Microsoft Entra ID 관리자가 이 AI Data Engine 인스턴스에 대한 AI Data Engine 애플리케이션을 등록하고 디렉터리(테넌트) ID와 애플리케이션(클라이언트) ID를 제공했습니다. link:configure-entra-id-mcp.html["관리형 AI 액세스를 위해 Microsoft Entra ID를 구성합니다"]을(를) 참조하십시오.




[[set-up-an-identity-provider]]
== ID 공급자를 설정하십시오

Microsoft Entra ID를 ID 공급자(IdP)로 연결하여 데이터 수집의 데이터 리소스에 대한 액세스를 인증하고 권한을 부여하십시오.

.시작하기 전에
* _AI Data Engine 관리자_ 역할이 있어야 합니다.
* 이 AI Data Engine 인스턴스에 대해 Microsoft Entra ID에 등록된 AI Data Engine 애플리케이션의 테넌트 ID와 애플리케이션(클라이언트) ID를 가지고 있습니다.


.단계
. NetApp Console에서 *AI 데이터 허브* > *AI Data Engine*으로 이동합니다.
. *구성* > *ID 공급자*를 선택합니다.
. *ID 공급자 추가*를 선택합니다.
+
*ID 공급자 추가* 패널이 열립니다.

. *ID 공급자 선택*에서 *Microsoft EntraID*를 선택합니다.
. *Entra Tenant ID*에 Entra ID 테넌트의 디렉터리(테넌트) ID를 입력합니다.
. *애플리케이션(클라이언트) ID*에는 AI Data Engine 애플리케이션의 애플리케이션(클라이언트) ID를 입력하십시오.
+

IMPORTANT: GUID인 애플리케이션(클라이언트) ID를 입력하십시오. 애플리케이션 ID URI를 입력하지 마십시오. 토큰은 GUID로 AI Data Engine 애플리케이션을 식별하므로 URI로 인해 로그인에 실패합니다.

+
Microsoft Entra ID 구성의 식별자를 사용하십시오. AI Data Engine은 두 값의 형식을 확인하고 테넌트가 존재하는지 확인합니다. *잘못된 ID* 메시지가 표시되면 값을 확인하고 수정한 후 다시 시도하십시오.

. *ID 공급자 추가*를 선택합니다.


설정이 완료되면 AI Data Engine에 *ID 공급자가 성공적으로 생성되었습니다.*라는 확인 메시지가 표시됩니다. 공급자가 *ID 공급자* 목록에 나타납니다. 계속 진행하기 전에 *연결 상태*가 *연결됨*인지 확인하십시오.

AI 클라이언트에서 사용하는 클라이언트 ID와 동일한 애플리케이션(클라이언트) ID를 사용하십시오.

NetApp Console이 ID 공급자 및 수집 설정을 MCP 서버에 비동기적으로 적용하기 때문에 변경 사항이 즉시 적용되지 않을 수 있습니다.

ID 공급자를 추가한다고 해서 자동으로 데이터 수집과 연결되는 것은 아닙니다. AI 애플리케이션이 인증 및 권한 부여를 통해 해당 리소스에 액세스할 수 있도록 수집을 구성할 때 ID 공급자를 선택하십시오. <<configure-collections-for-mcp,MCP용 컬렉션을 구성합니다>>을(를) 참조하십시오. 어떤 수집에서도 사용하지 않는 경우에만 ID 공급자를 삭제할 수 있습니다. ID 공급자를 편집하려면 link:maintain-mcp-setup.html#update-an-identity-provider["ID 공급자 업데이트"]을(를) 참조하십시오.



[[configure-collections-for-mcp]]
== MCP용 컬렉션을 구성합니다

ID 공급자를 설정하고 컬렉션을 생성한 후 NetApp Console에서 MCP용 컬렉션을 구성합니다. 컬렉션에 액세스할 수 있는 ID 공급자와 사용자 범위를 선택한 다음, AI 클라이언트를 위한 MCP 서버 URL 또는 클라이언트별 구성 스니펫을 복사합니다. link:manage-data-collections.html#configure-a-collection-for-mcp["MCP용 컬렉션 구성"]을(를) 참조하십시오.



[[verify-your-configuration]]
== 구성을 확인하십시오

사용자가 연결하기 전에 다음 사항이 모두 충족되는지 확인하십시오. 애플리케이션 ID URI, 범위, 테넌트 ID 및 클라이언트 ID는 Entra ID, NetApp Console 및 AI 클라이언트에서 정확히 일치해야 합니다.

*AIDE 클러스터 호스트*

* AIDE 클러스터 호스트 이름은 Entra ID에서 인증된 도메인에 있습니다.
* 사용자 컴퓨터에서 호스트 이름이 확인됩니다.
* 호스트는 클라이언트 컴퓨터가 신뢰하는 인증서를 제공합니다.
* MCP 서버의 잘 알려진 엔드포인트는 예상되는 응답을 반환합니다. link:prepare-mcp-host.html#verify-the-host["호스트를 확인하십시오"]을 참조하십시오.


*Microsoft Entra ID*

* 이 AI Data Engine 인스턴스에는 전용 애플리케이션이 등록되어 있습니다.
* 애플리케이션 ID URI는  `\https://<host>/mcp/tools`입니다.
*  `power_users` 스코프가 존재하며, 매니페스트에서  `requestedAccessTokenVersion`이(가)  `2`(으)로 설정되어 있습니다.
* 각 AI 클라이언트마다 리디렉션 URI가 등록되며, 공개 클라이언트 흐름이 허용됩니다.
*  `AIDEPowerUsers` 앱 역할이 사용자에게 할당됩니다.


*NetApp Console*

* Entra ID ID 공급자는 테넌트 ID와 애플리케이션(클라이언트) ID를 가지고 있으며 연결 상태는 *연결됨*입니다.
* *MCP 연결 활성화*는 *MCP 컬렉션* > *MCP 설정* > *MCP 서버 연결*에서 켜져 있습니다.
* MCP 서버의 상태가 *실행 중*입니다.
* 해당 컬렉션은 ID 공급자 및  `power_users` 범위를 사용하여 MCP에 맞게 구성되어 있습니다.
* MCP 코드 조각을 생성하셨습니다.


*AI 클라이언트*

* AI 클라이언트에 코드 조각을 추가하셨습니다.
* 클라이언트 ID는 애플리케이션(클라이언트) ID입니다.
* 범위는 애플리케이션 ID URI에  `/power_users`를 더한 값입니다.
* 한 번 로그인하면 AI Data Engine 툴 목록이 표시됩니다.
