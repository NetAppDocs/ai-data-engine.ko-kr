= AI Data Engine 아키텍처
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
AI Data Engine(AIDE)은 사용자가 제공하는 인프라에서 실행됩니다. Metadata Engine은 스토리지를 스캔하여 검색 가능한 카탈로그를 구축합니다. NetApp Console은 콘솔 에이전트를 통해 배포를 관리합니다. 모델 컨텍스트 프로토콜(MCP) 서버 옵션을 사용하면 AI 클라이언트가 사용자가 설정한 범위 내에서 카탈로그를 검색할 수 있습니다.



[[components]]
== 구성 요소

NetApp Console의 AI Data Engine 대시보드, 조사 및 정책은 모두 메타데이터 카탈로그에서 작동합니다. 다음 구성 요소는 카탈로그를 구축하고, 이를 NetApp Console에 연결하며, AI 클라이언트에 대한 관리형 액세스를 제공합니다.



[[metadata-engine]]
=== Metadata Engine

Metadata Engine은 AI Data Engine의 핵심 기능입니다. 연결한 데이터 소스를 스캔하여 메타데이터를 추출하고 검색 가능한 카탈로그에 저장합니다. 파일 내용을 읽거나 분류하지 않습니다. Metadata Engine은 각 스캔 주기마다 카탈로그를 업데이트하여 스토리지 시스템 전반의 추가, 변경 및 삭제를 감지합니다.



[[netapp-console-agent]]
=== NetApp Console 에이전트

AI Data Engine을 사용하려면 환경에 NetApp Console 에이전트가 배포되어 있어야 합니다. Console 에이전트는 환경과 NetApp Console 간의 연결을 유지하는 범용 NetApp 플랫폼 구성 요소입니다. 이 에이전트는 NetApp Console과 AI Data Engine 배포 간의 인증 및 통신을 처리합니다. 스캔 및 카탈로그 서비스는 Console 에이전트가 아닌 AI Data Engine 배포에서 실행됩니다.


NOTE: 콘솔 에이전트는 AI Data Engine에만 국한되지 않습니다. 다른 NetApp 서비스용으로 이미 콘솔 에이전트가 배포된 경우 동일한 에이전트를 사용할 수 있습니다. 콘솔 에이전트 배포 지침은 link:https://docs.netapp.com/us-en/console-setup-admin/concept-agents.html["NetApp Console 에이전트 설명서"]을(를) 참조하십시오.



[[governed-access-gateway]]
=== 관리형 액세스 게이트웨이

관리형 액세스 게이트웨이는 AI Data Engine의 MCP 서버입니다. 이를 통해 AI 클라이언트는 메타데이터 카탈로그를 검색할 수 있습니다. 게이트웨이는 AI Data Engine 배포 환경에서 실행되며, AI 클라이언트는 회사 네트워크 또는 VPN을 통해 HTTPS로 게이트웨이에 연결합니다. Console 에이전트는 MCP 트래픽을 중계하지 않습니다.

Microsoft Entra ID는 사용자를 인증하며, 게이트웨이는 각 AI 클라이언트가 사용자가 검색 권한을 부여받은 컬렉션만 검색하도록 제한합니다. 게이트웨이는 메타데이터 검색 및 태깅만 지원하며, 고급 사용자만 파일에 태그를 지정할 수 있습니다. 파일 내용은 가져오지 않습니다.

link:../mcp/learn-about-mcp.html["통제된 AI 액세스에 대해 자세히 알아보십시오"].



[[deployment-types]]
== 배포 유형

AI Data Engine은 두 가지 배포 유형을 지원합니다. 두 유형 모두 Kubernetes에서 AI Data Engine 서비스를 실행합니다.

AIDE 단일 노드 배포:: 사용자가 제공하는 단일 Linux VM에서 실행됩니다. 설치 프로그램은 k3s 및 지원 구성 요소를 자동으로 프로비저닝합니다. 단일 노드 배포는 고가용성 또는 수평 확장을 제공하지 않습니다.
AIDE 다중 노드 배포:: 사용자가 제공하는 Kubernetes 클러스터에서 실행되며 고가용성이 요구되는 대규모 환경에 적합합니다.


지원되는 플랫폼, 사이징 및 인프라 요구 사항에 대해서는 link:../deploy/aide-requirements.html["AIDE 요구 사항"]을(를) 참조하십시오.

각 배포 유형에는 아웃바운드 프록시를 통해서만 인터넷에 연결되는 환경을 위한 별도의 절차도 있습니다. link:../deploy/configure-proxy.html["AI Data Engine용 프록시에 대해 알아보기"]를 참조하십시오.

link:../deploy/deployment-overview.html["배포 옵션에 대해 자세히 알아보십시오."].



[[data-flow]]
== 데이터 흐름

AI Data Engine은 두 가지 별도의 경로를 사용합니다. 하나는 카탈로그를 구축하여 NetApp Console에 제공하는 경로이고, 다른 하나는 AI 클라이언트에 제공하는 경로입니다.



[[metadata-scanning-and-netapp-console-access]]
=== 메타데이터 스캔 및 NetApp 콘솔 액세스

. 관리하는 인프라에 AI Data Engine을 배포하고 NetApp Console 에이전트에 연결합니다.
. AI Data Engine이 카탈로그화할 데이터 소스를 *데이터 소스*에서 연결합니다. 자세한 내용은 link:../data-sources/connect-data-source.html["데이터 소스 연결"]을(를) 참조하십시오.
. Metadata Engine은 데이터 소스를 스캔하여 메타데이터를 추출하고 카탈로그에 인덱싱합니다.
. NetApp Console에서 대시보드는 카탈로그의 스토리지 인사이트를 표시하며, 조사 기능을 사용하면 메타데이터 필터를 통해 카탈로그를 직접 쿼리할 수 있습니다.
. 검색 조건을 정책으로 저장하고 다시 실행하여 일치하는 파일을 식별할 수 있으며, Investigation에서 파일에 대한 조치를 취할 수 있습니다.



NOTE: 카탈로그에는 스캔 중에 수집된 메타데이터가 반영됩니다. 소스 파일의 변경 사항은 해당 파일과 디렉터리를 다시 스캔하고 결과를 색인화한 후에 카탈로그에 나타납니다.



[[governed-ai-access]]
=== AI 접근 제어

. Microsoft Entra ID를 구성하고, AI 액세스를 위해 컬렉션을 활성화하고, 각 컬렉션을 검색할 수 있는 사용자를 선택합니다.
. 사용자가 AI 클라이언트를 Governed Access 게이트웨이의 HTTPS 엔드포인트에 연결하고 Microsoft Entra ID로 로그인합니다.
. 게이트웨이는 사용자의 접근을 확인하고 승인된 요청을 Metadata Engine에 전달합니다.
. AI 클라이언트는 사용자가 접근하고 작업을 수행할 수 있는 컬렉션에서 메타데이터를 검색합니다.
